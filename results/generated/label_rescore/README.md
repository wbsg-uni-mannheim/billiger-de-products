# Rescoring HierGAT and Ditto against the released test labels

All 27 variants (3 corner-case ratios x 3 dev-set sizes x 3 test conditions), German and
English, three seeds each. No model was retrained; the per-pair prediction dumps of the
original runs were re-joined to the released (audited) gold standards and re-scored.
Every number below is read out of the CSVs in this directory.

Generated by `results/generated/label_rescore/rescore.py`. All deliverables were committed
as **`45c262c`** on branch `roberta-per-pair-predictions`; the single follow-up commit on
that branch only inserts this sentence. Nothing was pushed.

Per-cell values: `validation_preaudit_mean.csv` (`f1_embedded_mean`), per seed in
`validation_preaudit_per_seed.csv`. **The pipeline is proven.**

### 1.1 Which file the pre-audit labels came from

Two different sources, and this matters:

* **English** — the pre-audit label files exist on disk:
  `.../Master-Thesis/data/processed_en/gold-standards_adjusted/preprocessed_products*_gs.pkl.gz`.
  For all 160 of 160 English prediction files the label column shipped inside the
  prediction dump is **element-wise identical** to that file (column `embedded_equals_preaudit`
  in `validation_preaudit_per_seed.csv`). Positional row alignment is therefore verified, not assumed.
* **German** — the pre-audit label file used by the German runs **does not exist anywhere on
  this machine.** The German dumps carry a label vector with 100-142 *extra* positives per
  variant. Every `*products*_gs*` file under both repositories was checked (pickle, json.gz,
  csv and the serialized Ditto/HierGAT `.txt`): none reproduces it. Details and the
  consequences are in section 3.

Because the German validation had to use the labels embedded in the dumps, it is a
reproduction of the published German numbers but **not** an independent check against a
stored German label file. The reproduction is nevertheless exact (<= 0.005 F1 pts), which
shows the published German column was computed from exactly these prediction rows.

## 3. Why the German column moves so much: two effects, not one

The German shift is **not** mostly the audit. Decomposing it
(`shift_decomposition.csv`):

| model | language | step 1: German label correction | step 2: audit row removal | total |
|---|---|---:|---:|---:|
| hiergat | de | -7.11 | +0.66 | -6.45 |
| hiergat | en | +0.00 | +0.87 | +0.87 |
| ditto | de | -6.73 | +0.87 | -5.86 |
| ditto | en | +0.00 | +0.95 | +0.95 |

* **Step 1** = scoring the same predictions against the *pre-audit* German gold standard
  on disk instead of the label vector embedded in the German dumps. For English this is
  exactly 0.00 by construction (the two are identical). For German it is about -7 F1 points.
* **Step 2** = the audit itself (removing the label-conflict rows). It is small and of the
  same magnitude in both languages: mean +0.66 to +0.95, per-variant range
  -0.51 to +3.12.

So **the audit is not what changes the paper's conclusion.** What changes it is that the
published German numbers were scored against a German test label vector that no released
or pre-audit gold standard reproduces.

### 3.1 Evidence for the German label vector

Per variant, the label column inside the German dumps vs. the pre-audit German gold
standard, compared row-by-row (both models agree on this vector wherever both exist):

| variant | rows | gold positives | dump positives | gold=1 & dump=1 | gold=1 & dump=0 | gold=0 & dump=1 |
|---|---:|---:|---:|---:|---:|---:|
| 20cc80rnd000un | 4478 | 408 | 481 | 401 | 7 | 80 |
| 20cc80rnd050un | 4455 | 355 | 460 | 348 | 7 | 112 |
| 20cc80rnd100un | 4459 | 366 | 459 | 355 | 11 | 104 |
| 50cc50rnd000un | 4470 | 366 | 471 | 358 | 8 | 113 |
| 50cc50rnd050un | 4466 | 355 | 466 | 343 | 12 | 123 |
| 50cc50rnd100un | 4479 | 382 | 479 | 360 | 22 | 119 |
| 80cc20rnd000un | 4474 | 346 | 476 | 334 | 12 | 142 |
| 80cc20rnd050un | 4470 | 371 | 475 | 351 | 20 | 124 |
| 80cc20rnd100un | 4463 | 356 | 465 | 326 | 30 | 139 |

The row **order** is nevertheless correct. For `20cc80rnd000un`, 401 of the 408 gold
positives fall on a row the dump also calls positive. Under a random permutation of the
same dump vector the expected overlap is 44 (200 permutations, max observed 65). Row counts
also match the pre-audit gold standard exactly for all nine variants
(4478/4455/4459/4470/4466/4479/4474/4470/4463), a distinctive fingerprint. The positional
prediction-row -> `pair_id` mapping used for the German join is therefore sound; only the
label column shipped with the German dumps is wrong.

### 3.2 A second, independent German defect: Ditto 80cc/large mixes two label sets

`src/models/ditto/output/prediction_de/` has no `id=1` or `id=2` for the `80cc20rnd`/`large`
cell. It has `id=0`, `id=3` and `id=4` -- the seed set the published 72.69 / 64.10 / 51.69
cell averages, confirming the earlier finding in `reports/table3_table6_consistency.md` §4.1.
Worse, the three runs were not scored against the same labels:

| run_id | dump positives (000un / 050un / 100un) | equals pre-audit German gold |
|---|---|---|
| 0 | 476 / 475 / 465 | no |
| 3 | 346 / 371 / 356 | yes |
| 4 | 346 / 371 / 356 | yes |

Run 0 (July) used the over-labelled German test file; runs 3 and 4 (August reruns) used the
corrected one. The published cell is a three-run mean over two different ground truths.
These are the only 6 of 159 German prediction files whose embedded labels match a gold standard on disk.

## 4. Joins

Join key: `pair_id`. The prediction dumps carry **no** identifier column (`label,prediction`
for HierGAT, `label,probability,prediction,threshold` for Ditto), so `pair_id` is taken
positionally from the pre-audit gold standard of the same variant and language -- verified
element-wise for English (section 1.1) and by the overlap argument for German (section 3.1).

Every join is an outer join with an indicator. Distinct shapes over all 319 joins:

| prediction rows | released gold rows | matched | prediction-only (unmatched) | gold-only (unmatched) | joins |
|---:|---:|---:|---:|---:|---:|
| 4455 | 4429 | 4429 | 26 | 0 | 36 |
| 4459 | 4449 | 4449 | 10 | 0 | 36 |
| 4463 | 4447 | 4447 | 16 | 0 | 36 |
| 4466 | 4418 | 4418 | 48 | 0 | 34 |
| 4470 | 4427 | 4427 | 43 | 0 | 35 |
| 4470 | 4437 | 4437 | 33 | 0 | 36 |
| 4474 | 4440 | 4440 | 34 | 0 | 36 |
| 4478 | 4454 | 4454 | 24 | 0 | 36 |
| 4479 | 4458 | 4458 | 21 | 0 | 34 |

* **Gold-only unmatched: 0 in every join** (total 0). Every released row has a prediction.
* **Prediction-only unmatched: 10-48 rows per join**, and these are exactly the rows the
  audit deleted. Verified directly: the released `pair_id` set is a strict subset of the
  pre-audit `pair_id` set for all 9 variants in both languages (0 released pairs absent from
  the pre-audit file), and **0 label flips** among the surviving pairs. The audit only
  removed rows.
* Per-join counts: `join_report.csv`; the unmatched count also appears as `n_unmatched` in
  `metrics_per_seed.csv`.

Deleted rows per variant (identical in both languages): 20cc 000un/050un/100un = 24/26/10,
50cc = 43/48/21, 80cc = 34/33/16.

## 5. Decision rule

The stored `prediction` column of each dump is used unchanged -- the same column the
original per-category evaluation scored (`src/models/{hiergat,ditto}/analysis_de.py`,
`analysis_en.py`, which compute `precision_recall_fscore_support(df.label, df.prediction,
average='binary')` and never re-threshold).

For Ditto that column is `probability > threshold`, where `threshold` is the per-run value
tuned on the validation set by `ditto_light/ditto.py:evaluate` and written into every row of
the dump. It was re-derived from the `probability` and `threshold` columns and reproduces
the stored `prediction` column **exactly in all 162 Ditto files** (strict `>`, not `>=`).
Thresholds actually used range over the runs (e.g. 0.80, 0.95); no fixed 0.5 cut is applied
anywhere. HierGAT emits a hard argmax and has no threshold.

Metric: precision / recall / F1 on the match class (`average='binary'`, `zero_division=0`),
identical to the original scripts.

## 8. What this means for the paper

1. The audit alone moves both matchers by under +1 F1 point on average in both languages
   and does not change any ranking. If the audit were the only issue, Tables 3 and 4 would
   need only a small uniform correction.
2. It is not the only issue. The published **German** HierGAT and Ditto columns were scored
   against a German test label vector carrying 100-142 spurious positives per variant that
   matches no gold standard, released or pre-audit, anywhere on this machine. Scoring the
   identical predictions against the released German labels costs HierGAT -6.45 and Ditto
   -5.86 F1 points on average.
3. The published **English** columns are clean: their labels are the pre-audit gold standard
   on disk, verified element-wise, and the audit lifts them by +0.87 (HierGAT) / +0.95 (Ditto).
4. Consequently the reported language effect inverts. HierGAT goes from a published mean
   EN-DE delta of +0.42 to **+7.74**, Ditto from -5.73 to **+1.08**; English leads on 26/27
   and 24/27 variants respectively, against 10/27 and 4/27 as published.
5. The RoBERTa, R-SupCon, WordCooc and Magellan rows were not part of this task and are
   unaffected by anything measured here. Whether their German columns used the same
   over-labelled test file is **not** established by this work and should be checked before
   any table is rewritten -- if they did, the German column of Table 3 moves as a block
   rather than only for these two matchers.
